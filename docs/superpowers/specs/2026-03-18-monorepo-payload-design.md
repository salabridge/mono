# Monorepo + Payload CMS Migration Design

**Date:** 2026-03-18
**Project:** Salabridge Family Recipes
**Status:** Approved

## Overview

Convert the existing single SvelteKit app into a Turborepo + pnpm workspaces monorepo. Add Payload CMS as a standalone Node/Express app that owns all content and authentication. The SvelteKit frontend consumes Payload exclusively via the Local API through a shared `packages/cms` package.

## Monorepo Structure

```
salabridge/
├── pnpm-workspace.yaml
├── turbo.json
├── package.json                 ← root (scripts only, no deps)
│
├── apps/
│   ├── web/                     ← SvelteKit frontend (@salabridge/web)
│   │   └── src/...
│   │
│   └── cms-server/              ← Payload + Express server (@salabridge/cms-server)
│       └── src/
│           └── server.ts
│
└── packages/
    ├── cms/                     ← Payload config + Local API (@salabridge/cms)
    │   └── src/
    │       ├── payload.config.ts
    │       ├── collections/
    │       └── index.ts
    │
    └── ui/                      ← Shared Svelte components (@salabridge/ui)
        └── src/
            └── components/
```

The existing `packages/db` stub and all Drizzle/Lucia code are removed. All current SvelteKit source moves into `apps/web`. Existing Google OAuth code (`src/routes/login/google/`) is deleted now; it may be re-added later via a Payload plugin.

## Package Dependency Graph

```
apps/web         → @salabridge/cms, @salabridge/ui
apps/cms-server  → @salabridge/cms
packages/cms     → (no workspace deps)
packages/ui      → (no workspace deps)
```

Each app's `package.json` must declare workspace siblings using `"workspace:*"`.

## Package Responsibilities

### `packages/cms` (@salabridge/cms)

The authoritative Payload configuration package. Contains `payload.config.ts` with all collection definitions. Exports:
- `getPayload()` — initializes and returns the Payload Local API instance. The config object is **imported directly** (not via `PAYLOAD_CONFIG_PATH`) so callers do not need that env var. Uses Payload v2's Local API pattern: `payload.init({ config, secret, db })` with **no `express` argument**, which tells Payload to initialize only the DB connection (no HTTP server, no port binding). The initialization Promise is memoized at module scope — concurrent callers await the same Promise, preventing duplicate inits on cold starts.
- All collection config objects
- TypeScript types generated by `payload generate:types`: `Recipe`, `Ingredient`, `Tag`, `User`, `Media` (output to `dist/payload-types.ts`)
- Typed query helpers: `getRecipes()`, `getRecipeBySlug(slug)`, etc.

**Generated types** (`dist/payload-types.ts`) are produced at build time by the `packages/cms` build script (`payload generate:types && tsc`). They are not committed to the repository. The Turborepo `^build` dependency ensures they exist before downstream apps compile.

**Bootstrap note:** On a fresh checkout, `pnpm --filter @salabridge/cms build` must be run once before `apps/web`'s dev server will type-check cleanly. The root `pnpm dev` script handles this automatically via Turborepo's `^build` dependency on the `dev` task, but it is worth calling out explicitly for contributors.

**Two init paths for Payload:**
- `apps/web` calls `getPayload()` → Local API only, no HTTP server, config imported directly
- `apps/cms-server` calls `payload.init({ config, secret, db, express: app })` → full server with Admin UI; also reads `PAYLOAD_CONFIG_PATH` for CLI commands (migrations, generate:types)

### `packages/ui` (@salabridge/ui)

Moves existing components out of `apps/web/src/lib/components`. Uses `@sveltejs/package` to package the library. Exports raw `.svelte` source files (no pre-compilation). `apps/web`'s `vite.config.ts` must add `@salabridge/ui` to `ssr.noExternal` to prevent Vite from treating it as an external dependency during SSR builds:

```ts
// apps/web/vite.config.ts
ssr: { noExternal: ['@salabridge/ui'] }
```

Exports: Button, Input, Toggle, Header, Navbar. No business logic — purely presentational.

### `apps/cms-server` (@salabridge/cms-server)

A thin Express server. Imports config from `@salabridge/cms`, calls `payload.init({ config, express: app })`, and starts listening. Serves Payload's built-in Admin UI at `/admin`. Also sets `PAYLOAD_CONFIG_PATH` for Payload CLI commands (migrations, type generation) run from this directory. Deployed on a persistent Node host (e.g., Railway or Render).

### `apps/web` (@salabridge/web)

The SvelteKit frontend. Retains `adapter-vercel` for Vercel deployment. Drops Lucia, arctic, and Drizzle. Imports components from `@salabridge/ui`, data helpers from `@salabridge/cms`, and retains `jose` for JWT verification (see Auth Flow). `src/app.d.ts` is updated: `event.locals.session` is removed; `event.locals.user` is typed as `import('@salabridge/cms').User | null`.

## Payload Collections & Data Model

The Payload Recipes and Ingredients collections are a deliberate redesign, not a direct migration of the existing Drizzle schema. The current Drizzle schema (Recipes: `title`, `shortTitle`, `body`; Ingredients: `name`, `description`, `url`, `imageUrl`) is replaced by the richer Payload model below. No existing production data needs to be migrated.

### Users
Payload's built-in auth collection. Fields: `name`, `email` (built-in), `role` (`admin` | `member`). Replaces Lucia's `users`, `sessions`, and `keys` tables plus the custom `auth` Postgres schema.

### Recipes
Core content collection. Fields:
- `title` (text)
- `slug` (text, auto-generated, indexed)
- `tagline` (text)
- `heroImage` (upload → Media)
- `prepTime`, `cookTime` (number, minutes)
- `ingredients` (array: `{ ingredient: relationship → Ingredients, quantity: text }`)
- `tags` (relationship → Tags, hasMany)
- `steps` (array: `{ instruction: richText, photo: upload, stepTime: number }`)
- `status` (`draft` | `published`)

### Ingredients
Lookup collection. Fields: `name` (text), `unit` (select — enumerated values: `g`, `kg`, `oz`, `lb`, `ml`, `l`, `tsp`, `tbsp`, `cup`, `piece`, `pinch`, `to taste`).

### Tags
Lookup collection. Fields: `name` (text), `slug` (text).

### Media
Payload's built-in upload collection for hero images and step photos. Local storage in dev; S3-swappable in production via environment config.

## Turborepo Pipeline

```json
{
  "tasks": {
    "build": {
      "dependsOn": ["^build"],
      "outputs": [".svelte-kit/**", "dist/**"]
    },
    "dev":   { "cache": false, "persistent": true },
    "lint":  { "dependsOn": ["^build"] },
    "check": { "dependsOn": ["^build"] }
  }
}
```

`packages/cms` build script: `payload generate:types && tsc` (output to `dist/`). Turborepo's `^build` dependency ensures this runs before either app builds.

`pnpm dev` from root starts all concurrently:
- `apps/cms-server` → Express + Payload on port `3000` (Admin UI at `http://localhost:3000/admin`)
- `apps/web` → SvelteKit on port `5173`

Both apps share one Postgres database in dev. Payload manages its own schema migrations (`payload migrate`). Build caching applies to `build` and `check`; `dev` is never cached.

**Root `package.json` scripts:**
```json
{
  "dev":   "turbo dev",
  "build": "turbo build",
  "lint":  "turbo lint",
  "check": "turbo check"
}
```

## Auth Flow (Replacing Lucia)

Payload's built-in auth (email/password, JWT sessions) replaces the entire Lucia stack.

**Login:** `/login` in `apps/web` submits to a `+page.server.ts` form action. The action calls `payload.login({ collection: 'users', data: { email, password } })` via the Local API. The returned `token` string is then explicitly set by the action:
```ts
cookies.set('payload-token', token, {
  httpOnly: true,
  path: '/',
  secure: true,
  sameSite: 'lax'
});
```

**Session validation:** `hooks.server.ts` runs on every request. It reads the `payload-token` cookie and **verifies** the JWT signature using `jose` with `PAYLOAD_SECRET` as the symmetric signing key (Payload v2 signs JWTs with this secret). A verified token yields the user ID and expiry. The handler then calls `payload.findByID({ collection: 'users', id: userId })` to hydrate `event.locals.user`. An expired, tampered, or missing token results in `locals.user = null`. `PAYLOAD_SECRET` must be present in `apps/web`'s environment and must match the value used by `apps/cms-server`.

**`app.d.ts` update:** `event.locals.session` is removed; `event.locals.user` is typed as `import('@salabridge/cms').User | null`.

**Protected routes:** `/admin` in `apps/web` checks `locals.user?.role === 'admin'`.

**Logout:** `/logout` action calls `cookies.delete('payload-token', { path: '/' })`.

**Payload Admin UI** at `apps/cms-server` (port 3000) has its own independent session — a separate cookie from the SvelteKit `payload-token`. Only admins are given the CMS server URL.

## Migration Notes

This app has no existing production data to migrate. The old Postgres tables must be dropped in dependency order to avoid FK violations:

1. `public.recipe_ingredients`
2. `public.recipes`
3. `auth.sessions`, `auth.keys`
4. `public.ingredients`
5. `auth.users`

After dropping, Payload creates its own schema via `payload migrate`. A fresh admin user is seeded via the Payload Admin UI on first run.

## Environment Variables

| Variable | Required by | Notes |
|----------|-------------|-------|
| `DATABASE_URL` | `apps/cms-server`, `apps/web` | Postgres connection string |
| `PAYLOAD_SECRET` | `apps/cms-server`, `apps/web` | JWT signing secret — must be identical in both apps |
| `PAYLOAD_CONFIG_PATH` | `apps/cms-server` | For CLI commands only (dev: `.ts` source via `tsx`; production: `dist/payload.config.js`) |
| `PORT` | `apps/cms-server` | HTTP port (default: `3000`) |
| `PUBLIC_CMS_URL` | `apps/web` | Optional. URL of `apps/cms-server`. Only needed if `apps/web` needs to construct absolute media URLs (e.g., linking to images hosted on the CMS server). Not required if media is served via S3 or a CDN in production. |
